系统简介
了解 FT1-MONITOR 的功能与架构

液奶过程监控系统 (FT1-MONITOR) 是一套面向乳制品生产过程的实时 SPC 分析与智能预警平台。系统集成多源仪器数据自动采集、统计过程控制 (SPC) 分析、过程能力评估、AI 指标预测和分级预警功能，帮助质量管理人员实时掌握生产过程稳定性。

桌面应用层 Tauri v2 + Rust 原生桌面应用，系统托盘、声音告警、开机自启
↓
前端展示层 React 18 + ECharts 5 9 个功能页面，深色科技主题，WebSocket 实时推送
↓
后端服务层 FastAPI + Python 3.11 SPC 引擎、AI 预测引擎、自适应采集调度、API Key 认证
↓
数据存储层 SQLite + SQL Server + MDB 本地 SQLite (WAL) + 三类仪器数据源对接
FT1SQL Server
FT120MDB 文件
FTAPerten DB
→

→

快速开始
3 分钟完成安装并启动系统
1克隆代码仓库
Terminal
# 克隆项目到本地 git clone https://gitee.com/aerlee/FT1-MONITOR.git cd FT1-MONITOR
2安装依赖
后端依赖
# 创建 Python 虚拟环境并安装依赖 cd backend python -m venv venv # Windows venv\Scripts\activate # Linux / macOS source venv/bin/activate pip install -r requirements.txt
前端依赖
cd ../frontend npm install
3启动系统
Windows - 一键启动（开发模式）
# 回到项目根目录 cd .. # 运行 Windows 启动脚本 scripts\dev.bat
Linux / macOS - 一键启动（开发模式）
# 回到项目根目录 cd .. # 添加执行权限并运行 chmod +x scripts/dev.sh ./scripts/dev.sh
💡
启动成功后，前端访问 http://localhost:5173，后端 API 文档访问 http://localhost:18080/docs。系统默认使用 Mock 模拟数据，无需连接真实仪器即可体验全部功能。
🛠
开发模式
前后端分离，支持热更新

开发模式下，前端 Vite 开发服务器和后端 Uvicorn 服务分别运行，支持代码热更新。适合开发调试阶段使用。

服务地址说明
前端http://localhost:5173Vite 开发服务器，代码修改即时生效
后端http://localhost:18080Uvicorn 服务，--reload 模式自动重启
API 文档http://localhost:18080/docsFastAPI 自动生成的 Swagger 文档
启动脚本
Windows
scripts\dev.bat
Linux / macOS
chmod +x scripts/dev.sh ./scripts/dev.sh
停止服务
Linux / macOS
./scripts/stop.sh
ⓘ
Windows 用户直接关闭命令行窗口即可停止所有服务。
⚖
生产模式
前端构建为静态文件，后端统一托管

生产模式下，前端代码构建为静态文件，由后端 FastAPI 服务统一托管。只需一个端口即可访问完整系统。

一键启动
Windows
scripts\start.bat
Linux / macOS
chmod +x scripts/start.sh ./scripts/start.sh
💡
生产模式启动后访问 http://localhost:18080，前端和 API 均通过同一端口提供服务。
手动部署（高级）
手动构建前端
cd frontend npm run build # 生成的静态文件在 frontend/dist/ 目录
启动后端服务
cd .. python -m uvicorn backend.main:app --host 0.0.0.0 --port 18080
Nginx 反向代理配置（可选）

如需使用 Nginx 作为反向代理，参考以下配置：

nginx.conf
server { listen 80; server_name localhost; # 前端静态文件 location / { root /path/to/frontend/dist; try_files $uri $uri/ /index.html; } # API 代理 location /api { proxy_pass http://localhost:18080; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; } # WebSocket 代理 location /api/ws { proxy_pass http://localhost:18080; proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade"; } }

系统启动后默认使用 Mock 模拟数据。如需连接真实仪器，请在「配置管理」页面完成以下配置。所有配置均支持热更新，保存后立即生效。

配置项说明配置位置
仪器数据源选择 FT1 / FT120 / FTA 并填写连接信息配置管理 → 仪器选择
品项管理启用/停用品项，设置别名和样品类别配置管理 → 品项管理
规格限为每个指标设置 USL / LSL / 目标值品项编辑弹窗
预警规则启用/禁用 Nelson 判异规则配置管理 → 预警规则
排除关键词排除基准样等不参与分析的数据配置管理 → 排除备注
指标别名为指标设置中文显示名称配置管理 → 检验项目别名

仪器接入指南
连接 FT1 / FT120 / FTA 乳品分析仪
FT1 乳品分析仪（SQL Server）
确认网络连通
确保运行系统的电脑能访问 FT1 仪器的 SQL Server 数据库（默认端口 1433 或自定义端口）
填写连接信息
在配置管理 → 仪器选择中选择 FT1，填写服务器地址（格式：主机名\实例名,端口）、数据库名称（默认 MSCFT1）、认证方式
测试连接
点击「测试连接」验证配置是否正确，绿色提示表示连接成功
保存并采集
点击「保存配置」，系统自动连接数据源并预览最近数据，确认后开始自动采集
FT120 乳品分析仪（MDB 文件）
获取 MDB 文件路径
找到 FT120 仪器导出的 Access 数据库文件（.mdb），记录完整文件路径
配置文件路径和表映射
在配置管理中选择 FT120，填写 MDB 文件路径，确认表名和字段映射（通常使用默认值即可）
测试并保存
测试连接成功后保存配置，系统开始从 MDB 文件采集数据
FTA Perten 乳品分析仪（SQL Server）

配置方式与 FT1 类似，连接 Perten 仪器的独立 SQL Server 实例。默认数据库名为 Pert_Application，默认使用 SQL Server 认证（用户名 sa）。

常见问题
安装和使用中的常见疑问
没有真实仪器数据，能否体验系统功能？ ▼
可以。系统默认使用 Mock 模拟数据源，会自动生成仿真检测数据。启动后即可体验全部功能，包括 SPC 控制图、过程能力分析、智能预测、告警管理等。
pip install 速度很慢怎么办？ ▼
可使用国内镜像源加速安装：
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
npm install 报错怎么办？ ▼
1. 确认 Node.js 版本 ≥ 18（运行 node -v 查看）
2. 尝试清除缓存：npm cache clean --force
3. 使用国内镜像：npm config set registry https://registry.npmmirror.com
4. 删除 node_modules 目录后重新安装
连接 SQL Server 数据库失败？ ▼
1. 确认数据库服务器地址和端口正确
2. 确认网络可达（尝试 telnet 服务器IP 端口）
3. 确认 SQL Server 已启用 TCP/IP 协议
4. 确认认证方式和账号密码正确
5. 检查防火墙是否放行了数据库端口
端口 18080 被占用怎么办？ ▼
修改启动命令中的端口号：
python -m uvicorn backend.main:app --host 0.0.0.0 --port 18081
同时需要修改前端 vite.config.ts 中的代理端口配置。
数据存储在哪里？如何备份？ ▼
所有数据存储在项目根目录的 data/ 文件夹中的 SQLite 数据库文件。配置文件（*.json）也在项目根目录。备份时只需复制整个项目目录或 data/ 和 *.json 文件即可。

故障排查
常见问题的诊断与解决
问题现象可能原因解决方案
页面空白或加载失败后端服务未启动检查后端进程是否运行，查看 logs/backend.log
数据不更新采集服务未运行或数据源断开检查配置管理页面的采集状态面板
控制图无数据品项未启用或无规格限在配置管理中启用品项并设置规格限
告警不触发Nelson 规则被禁用在配置管理中启用所需的预警规则
WebSocket 断连网络不稳定或服务重启刷新页面，系统会自动重连
预测页面报错历史数据不足至少需要 30 条以上数据才能进行预测
